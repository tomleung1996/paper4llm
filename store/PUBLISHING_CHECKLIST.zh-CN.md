# Chrome Web Store 发布清单

[English](PUBLISHING_CHECKLIST.md) | 简体中文

本清单适用于首次公开发布和后续更新。Chrome Web Store 的字段与素材要求可能变化，最终应以 Developer Dashboard 当时显示的要求为准。

## 1. 开源仓库

- [ ] 确认最终源码归档中包含 MIT `LICENSE` 文件。
- [ ] 创建公开仓库，并确认其中没有凭据、Cookie、私人论文内容或仅供本地使用的文件。
- [ ] 不要将 `backups/` 提交到公开仓库；其中保存的是本地回退副本，而非发布素材。
- [ ] 确认主页、支持、隐私政策和安全报告链接均指向公开仓库。
- [ ] 开启 GitHub Issues 作为公开支持渠道，并通过 GitHub Security Advisories 接收私密漏洞报告。
- [ ] 确认每份公开文档都有完整的英文和简体中文版本，且语言切换链接有效。

## 2. 扩展安装包

- [ ] 确认 `manifest.json`、`package.json` 和发布文档中的发布版本均为 `1.1.0`。
- [ ] 复核 `activeTab`、`scripting`、网站访问权限和内容脚本匹配范围，删除最终实现不需要的权限。
- [ ] 确认 `STORE_LISTING.zh-CN.md` 中的权限说明与上传包内的 `manifest.json` 完全一致。
- [ ] 确认所有可执行代码都随扩展打包，不加载远程代码。
- [ ] 运行 `npm run release:check`。
- [ ] 在干净的 Chrome 配置文件中加载未打包扩展，并测试每个受支持的出版商。
- [ ] 测试英文、简体中文和自动语言选择。
- [ ] 测试复制、`.md` 下载、YAML 开关、图片链接开关、长文本输出和未映射引用报告。
- [ ] 检查登录、付费墙、Cookie 和人机验证页面上的预期行为；扩展不得绕过这些机制。
- [ ] 检查生成的 ZIP，确认 `manifest.json` 位于压缩包根目录，且不包含开发专用文件或私人文件。

## 3. 商店素材

- [ ] 使用最终的 128×128 扩展图标。
- [ ] 从 `store/assets/generated/` 中选择对应语言的 440×280 小型宣传图。
- [ ] 从 `store/assets/generated/` 中选择 1280×800 商店截图。
- [ ] 为英文和简体中文商店页面分别上传对应的本地化素材。
- [ ] 展示真实的扩展界面和代表性 Markdown 输出，不暗示尚未支持的能力。
- [ ] 按最终上传尺寸检查所有图片的可读性、安全边距和品牌一致性。
- [ ] 上传前立即在 Developer Dashboard 中再次确认素材尺寸要求。

## 4. Developer Dashboard

### 商店详情

- [ ] 填写本地化的名称、简短说明、详细说明、类别、语言、图标、截图、主页和支持网址。
- [ ] 使用 `STORE_LISTING.md` 和 `STORE_LISTING.zh-CN.md` 中对应语言的文案。
- [ ] 保留独立项目及与出版商无隶属或背书关系的声明。

### 隐私

- [ ] 声明单一用途：将当前受支持的学术论文转换为保留引文链接的 Markdown。
- [ ] 提供公开可访问的 HTTPS 隐私政策网址。
- [ ] 用通俗语言解释每项申请的权限。
- [ ] 将远程代码声明为**否**。
- [ ] 披露网页内容仅在本地处理，用于用户主动请求的转换。
- [ ] 对“当前网址”或“浏览记录”问题作保守且一致的回答：当前论文网址仅在本地用于识别出版商和标注来源，不收集跨标签页或长期浏览历史。
- [ ] 如果控制台询问用户设置，披露本地保存的界面语言偏好。
- [ ] 只有在核对最终安装包和隐私政策后，才确认符合 Chrome Web Store 用户数据政策及 Limited Use 要求。

### 分发与审核

- [ ] 选择公开可见性和目标地区。
- [ ] 添加商店文案草稿中的审核说明和代表性网址。
- [ ] 确认审核员无需提供 Paper for LLMs 账户或凭据；出版商自身要求的访问权限除外。
- [ ] 上传最终 ZIP。
- [ ] 如果希望在审核通过后自行选择公开时间，启用延迟发布。

## 5. 提交之后

- [ ] 关注审核状态并及时回答审核问题。
- [ ] 保持隐私政策、支持网址和安全报告渠道公开可访问。
- [ ] 为提交安装包所对应的源码提交创建标签；如有需要，可在 Release 中附上完全对应的 ZIP。
- [ ] 后续每次上传都应递增版本号、更新两种语言的更新日志、重新运行完整发布检查，并归档实际提交的安装包。
